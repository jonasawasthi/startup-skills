# Launch plans and roadmaps

Background: [launches](../../../knowledge/gtm/launches.md), [channels](../../../knowledge/gtm/channels-and-distribution.md).

## Launch phase card (one per phase that applies)

| Field | Content |
|---|---|
| Objective | One sentence, plus the exit criterion |
| Target audience | The segment and how many (a target) |
| Launch positioning | The angle for this phase (for example, "founding teachers" in a private beta) |
| Campaign strategy | The core idea and the sequence of moments |
| Channels | Primary channels only, with their experiments |
| Launch assets | Landing page, demo video, onboarding guide, email sequence, social posts, press note (only when needed) |
| Partnerships | Who amplifies, and what they get |
| Feedback collection | Interviews, in-product survey (PMF question after the second use), support log |
| Activation strategy | The activation event and how new users reach it |
| Post-launch follow-up | Day 1, 7 and 30 touchpoints; the relaunch trigger |

Phases: **pre-launch → waitlist → private beta → public beta → launch → post-launch**. Skip phases that don't apply, and say why (for example, "no waitlist: supply is recruited one-to-one").

**Product status gates each phase.** A `built` product can run a private beta. A public launch requires `live` (payments on, legal checks done). Launch platforms such as Product Hunt fit only when the target customers actually use them.

## Roadmaps

Phases end on day **30, 60, 90, 180 and 365**. Each phase has:

| Field | Notes |
|---|---|
| Objectives | 1–3, outcome-based |
| Priorities | What gets done first, and what is explicitly deferred |
| Tasks | id, owner, effort_days, cost, depends_on, deliverable |
| Deliverables | Concrete artefacts |
| Dependencies | Tasks, product readiness, legal, hires, partners |
| Suggested ownership | Roles in `team.roles`. Anyone else is a dependency (a hire or partner) |
| Resources | Tools and assets |
| Budget assumptions | Labelled assumptions, summed by the engine against `budget.available` |
| KPIs | From the KPI workbook |
| Success criteria | Thresholds that decide whether to continue, change or stop |

Realism rules (the engine enforces the first two):

1. Planned effort ≤ capacity. Aim for ≤ 85%, which leaves room for support and product work.
2. Spend ≤ available budget.
3. Months 1–3 focus on learning (discovery, the first channel experiments, activation). Scaling starts only after a channel shows a readable signal.
4. Hires appear as dependencies with a trigger ("hire a support lead when there are more than 50 active creators"), not as assumed capacity.
