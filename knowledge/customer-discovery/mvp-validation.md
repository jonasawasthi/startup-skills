# MVP validation

See also: [YC MVP](../yc/mvp.md).

## Attributed

- **Ries:** the MVP is the simplest version that lets a startup begin learning from customers.
- **Seibel (YC, 2019)** shares his approach to building an MVP and getting the first users before launch.

## How the skill applies this (original synthesis)

**An MVP is an experiment, so it needs an experiment card.** The questions it must answer:

| MVP form | Answers | Doesn't answer |
|---|---|---|
| Concierge (done by hand) | Will people use and pay for the *outcome*? | Can software deliver it cheaply? |
| Wizard-of-Oz (looks automated, is manual) | Will people use the *interface*? | Cost at scale |
| Single-feature product | Is the core job served? | Breadth of demand |
| Pre-sale before the product exists | Will people commit money? | Satisfaction after use |

**Validation signals, in rising order of strength:**

1. sign-up;
2. activation, meaning the core action is completed;
3. repeat use within the natural cycle;
4. payment;
5. renewal or a repeat purchase;
6. an unprompted referral.

**Status discipline.** An MVP that exists in code is `built`. It is `live` only when real users can get it, and pay where payment is part of the test. Results from friends and family are labelled as such.
